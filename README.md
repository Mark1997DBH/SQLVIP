# SQLVIP

一款用 Python 编写的多数据库 SQL 方言转换工具。左侧粘贴 SQL，选择源数据库和目标数据库，点击转换，右侧即可得到目标方言 SQL。

界面不依赖数据库连接，转换过程在本机完成。

![SQLVIP 界面](docs/screenshot.png)

## 支持的数据库

| 方言 | 标识 | 说明 |
| --- | --- | --- |
| IBM DB2 | `db2` | Db2 11.5+ 常用 SQL、`FETCH FIRST`、`CURRENT DATE`、`SYSIBM.SYSDUMMY1` |
| PostgreSQL | `postgres` | PostgreSQL 常用 SQL、`LIMIT/OFFSET`、标准函数 |
| Oracle | `oracle` | Oracle 12c/19c 常用 SQL、`DUAL`、`FETCH FIRST`、identity 列 |
| MySQL | `mysql` | MySQL 8.x 常用 SQL、`LIMIT`、反引号标识符、`AUTO_INCREMENT` |
| 达梦 DM8 | `dameng` | 基于 Oracle 兼容语法，支持 `LIMIT`、`FETCH FIRST`、`NVL`、`LISTAGG`、`IDENTITY` |

源库和目标库可任意组合，包含五种数据库之间的 25 种转换路径。相同数据库之间也可以转换，用于统一格式。

## 功能

- 左右分栏：左边输入 SQL，右边查看转换结果
- 一键转换、复制结果、交换源库/目标库、载入各数据库示例
- 支持查询、DDL、DML 和多条语句
- 格式化输出开关
- 解析错误会显示行号、列号和具体原因
- 针对潜在语义差异显示中文提示，例如 `ROWNUM`、`WITH UR`、JSON、字符串拼接空值语义
- FastAPI 提供 REST API，便于后续集成到其他系统
- 无 CDN、无前端构建步骤，离线即可运行

## Windows 单文件 EXE（推荐）

已打包：[dist/SQLVIP.exe](dist/SQLVIP.exe)，约 22 MB，适用于 Windows 10/11 x64，**无需安装 Python**。

![桌面控制窗口](docs/desktop-window.png)

使用方式：

1. 下载 `SQLVIP.exe`。
2. 双击运行，出现 SQLVIP 控制窗口。
3. 浏览器会自动打开 SQLVIP 页面；如果没有打开，点击「打开 SQLVIP」。
4. 关闭控制窗口即可退出本地服务。

说明：

- 单文件 EXE 首次启动时会解压运行文件，通常需要 1–3 秒。
- 默认使用 `127.0.0.1:8000`；如果端口被占用，会自动选择其他空闲端口，并在控制窗口中显示实际地址。
- 日志位于 `%LOCALAPPDATA%\SQLVIP\sqlvip.log`。
- EXE 未进行代码签名。Windows SmartScreen 可能提示“Windows 已保护你的电脑”，可点击「更多信息」→「仍要运行」。
- 如果希望指定端口，可在命令行运行：`SQLVIP.exe --port 9000`。
- 重新构建 EXE：双击 `build_exe.bat`，需要网络安装 PyInstaller。

要求：Python 3.10 或更高版本。

```bash
cd SQLVIP

# 建议使用虚拟环境
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
# source .venv/bin/activate

pip install -r requirements.txt
python run.py
```

打开：

```text
http://127.0.0.1:8000
```

Windows 也可以直接双击 `start.bat`。

指定端口：

```bash
python run.py --port 9000
```

开发模式（代码修改后自动重载）：

```bash
python run.py --reload
```

## 使用方式

1. 在左上角选择源数据库。
2. 在右上角选择目标数据库。
3. 在左侧输入或粘贴 SQL；也可以点击「载入示例」。
4. 点击「转换 SQL」，或按 `Ctrl + Enter`。
5. 在右侧查看结果，点击「复制」即可使用。

「交换」按钮会把当前目标 SQL 放回左侧，并反转源库和目标库，方便做往返转换。

## API

启动后访问 `http://127.0.0.1:8000/api/docs` 查看交互式文档。

### 转换

```http
POST /api/convert
Content-Type: application/json

{
  "sql": "SELECT * FROM users LIMIT 10;",
  "source": "mysql",
  "target": "oracle",
  "pretty": true
}
```

响应示例：

```json
{
  "ok": true,
  "sql": "SELECT\n  *\nFROM users\nFETCH FIRST 10 ROWS ONLY",
  "source": "mysql",
  "target": "oracle",
  "source_label": "MySQL",
  "target_label": "Oracle",
  "statement_count": 1,
  "elapsed_ms": 2,
  "pretty": true,
  "notes": [],
  "input_chars": 33,
  "output_chars": 46
}
```

解析失败时返回 HTTP 400：

```json
{
  "ok": false,
  "error": {
    "code": "PARSE_ERROR",
    "message": "无法解析第 1 行第 8 列的 SQL，请检查语法或切换源数据库。",
    "hint": "Expected expression but got ...",
    "line": 1,
    "column": 8
  }
}
```

### 其他接口

- `GET /api/health`：健康检查
- `GET /api/dialects`：支持的方言列表
- `GET /api/docs`：Swagger UI

## 转换规则举例

| 场景 | 输入 | 输出示例 |
| --- | --- | --- |
| MySQL 分页 → Oracle | `LIMIT 10` | `FETCH FIRST 10 ROWS ONLY` |
| DB2 分页 → MySQL | `FETCH FIRST 5 ROWS ONLY` | `LIMIT 5` |
| 达梦分页 → DB2 | `LIMIT 8` | `FETCH FIRST 8 ROWS ONLY` |
| 空值函数 | `IFNULL(a, 0)` / `NVL(a, 0)` | `COALESCE(a, 0)` |
| 当前时间 | `NOW()` | Oracle：`CURRENT_TIMESTAMP`；Db2：`CURRENT TIMESTAMP` |
| 时间格式化 | `DATE_FORMAT(d, '%Y-%m-%d')` | Oracle：`TO_CHAR(d, 'YYYY-MM-DD')` |
| 日期运算 | `DATE_SUB(NOW(), INTERVAL 30 DAY)` | Oracle：`CURRENT_TIMESTAMP - INTERVAL '30' DAY` |
| 字符串拼接 | MySQL `CONCAT(a, b, c)` | Oracle/达梦：`a || b || c` |
| 分组拼接 | `GROUP_CONCAT(name SEPARATOR ',')` | `LISTAGG(name, ',')` |
| Oracle 无 FROM 查询 | `SELECT 1` | `SELECT 1 FROM DUAL` |
| Db2 无 FROM 查询 | `SELECT 1` | `SELECT 1 FROM SYSIBM.SYSDUMMY1` |
| 自增列 | MySQL `AUTO_INCREMENT` | Oracle/Db2：`GENERATED BY DEFAULT AS IDENTITY`；达梦：`IDENTITY(1,1)` |
| 类型映射 | `BIGINT` / `BOOLEAN` / `DATETIME` | Oracle：`NUMBER(19)` / `NUMBER(1)` / `TIMESTAMP` |
| 简单 ROWNUM | `WHERE ROWNUM <= 10` | MySQL/PostgreSQL：`LIMIT 10`（会提示复核排序语义） |

## 设计说明

转换核心使用 [SQLGlot](https://github.com/tobymao/sqlglot) 将 SQL 解析为抽象语法树，再按目标方言生成 SQL。SQLGlot 原生支持 MySQL、PostgreSQL 和 Oracle；项目补充了：

- **Db2**：分页、`CURRENT DATE/TIME/TIMESTAMP`、`SYSIBM.SYSDUMMY1`、常用类型与日期函数
- **达梦 DM8**：复用 Oracle 兼容语法，补充数值类型映射和 `IDENTITY`
- **Oracle 迁移增强**：处理 MySQL 常见的 `BIGINT`、`BOOLEAN`、`DATETIME`、`AUTO_INCREMENT`、`TINYINT(1)` 和 `GROUP_CONCAT` 等差异
- **通用规范化**：`NOW()`、`IFNULL`、`NVL`、`CONCAT`、简单 `ROWNUM`、Db2 隔离级别后缀

## 已知限制

这是一个“语法快速转换”工具，不是数据库迁移平台的完整替代品：

- 不连接数据库，也不读取表结构、索引、约束和数据类型上下文
- 不转换存储过程、函数、触发器、包、游标等过程化代码
- 复杂 `ROWNUM` 分页、`CONNECT BY` 层次查询、JSON 路径、窗口帧、优化器提示等可能需要人工改写
- 字符串拼接对 `NULL` 的处理在 MySQL 与 Oracle/达梦之间不同，工具会提示，但不会自动改变业务语义
- 达梦的兼容模式、大小写敏感设置和具体版本会影响执行结果，建议在目标库中做一次验证
- Oracle 目标默认按 12c+ 语法生成（`FETCH FIRST`、identity 列）；如果使用 11g，请按提示调整
- 转换结果不保证可直接执行，请先在测试环境校验
